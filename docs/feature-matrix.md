# Python Support 功能矩阵（Feature Matrix）

本文档维护 `io.github.lithe-idea.python-support`插件在 6 个目标发布平台上的实现与真实执行验证状态（插件功能矩阵与测试证据仅在本插件仓库维护，不进入宿主仓库）。

## 状态定义

- `✅ 已验证`：已在目标平台实机完成打包安装、真实上游二进制/运行时进程执行及宿主端到端测试验证。
- `⏳ 待实机验证（pending）`：已在 `plugin.json`、脚本与对应平台归档（`dist/python-support-<version>-<platform>.zip`）中完成实现，并通过归档路径/大小写安全检查、Lithe Store 规则校验以及 Unix/Windows 双清单真实 Core `ValidatePluginManifest` 契约校验；但尚未在对应 OS/架构实机或 CI runner 上执行原生子进程工作流，严禁在未实跑前标为已验证。
- `🚧 待宿主开放（blocked on host capability）`：插件端协议与代码已完整实现并通过真实 Core 解码验证，待桌面宿主开放对应能力版本后启用清单声明。

## 宿主版本与验证

- 插件要求宿主声明 `toolchainProviders: 0`、`buildSystems: 1`、`buildProviders: 1`、`runConfigurationTypes: 0` 和 `languages: 0`。桌面 0.8.9 支持安装、当前文件运行和原有 Python 功能。支持 TextMate 首行匹配的桌面会额外识别无后缀脚本。
- `e2e/host/lithe-host.json` 固定桌面主线提交 `60885168`。
- 插件 CI 用同一个 macOS ARM64 ZIP 在 0.8.9 验证普通 Python 高亮、当前文件运行（含为项目固定的解释器和覆盖路径）、手动运行配置和依赖树，并在固定的桌面主线上运行完整宿主套件，额外覆盖设置预览、项目生成、解释器切换、pytest、debugpy 和无后缀脚本的编辑诊断。
- macOS ARM64 的工作台测试从 ZIP 安装插件，改变项目版本要求以切换外部解释器，检查全局候选和项目 `.venv` 信任，精确重跑一个参数化 pytest 用例并核对 JUnit。
- 无头工作台打开 `.py` 后，Pyrefly 返回所选环境独有模块的类型诊断。debugpy 使用同一环境执行当前文件，并将日志写入宿主分配目录。关闭后，已安装插件的文件清单和 SHA-256 与启动前一致。
- 宿主按 Core 的文件事实校验安装。程序链接到安装目录外的安装会以 `unsafePath` 被拒绝，包括在 macOS 和 Linux 上建在项目外的虚拟环境（venv、`uv venv`、virtualenv、Poetry、Pipenv）和 Homebrew 的 Python，固定、`VIRTUAL_ENV` 和发现规则都一样（[#2316](https://github.com/1lck/Lithe-IDEA/issues/2316)）。项目内环境由宿主信任流程单独处理。所以固定解释器的端到端用例固定的是 `PYTEST_PYTHON` 指向的真实安装。
