## 中文

- 「设置 › 语言与框架 › Python」顶部显示当前使用的 Python 解释器，点击可打开「工具链」页更换。下面的预览卡片按尚未保存的设置画出类型检查模式、诊断范围、自动导入补全和补全函数括号的效果。
- 「设置 › 构建、执行、部署 › 构建工具 › Python」显示 Lithe 查找解释器的顺序：项目固定的解释器和项目里的 `.venv`、`venv`、`.conda`，然后是全局设置，最后是自动发现。
- Pyrefly 分析、运行、测试和调试都使用「工具链」页为项目解析出的同一个解释器。
- 新增「隐藏类型错误」，替代原来的「显示类型错误」。开启后所有文件都不显示类型错误，包括有自己 Pyrefly 配置的项目；悬停、跳转和补全照常可用。
- 类型检查模式新增“宽松”预设。“自动”会沿用附近的 mypy 或 Pyright 配置，没有时按“基础”检查。
- 类型检查模式和自动导入路径风格的说明写明了它们和其他设置的关系，例如开启「隐藏类型错误」后预设不再显示类型错误，关闭「自动导入补全」后只有代码操作会用到路径风格。

### 升级与兼容性

Python Support v1.1.0 要求 Lithe 0.8.9 或更新版本。从 0.8.10 开始，Lithe 还能按 shebang 自动识别无后缀脚本。

v1.1.0 删除了「Python 解释器覆盖路径」设置。升级后，已经保存的路径不再生效，请在「设置 › 构建、执行、部署 › 工具链」为项目固定解释器。

调试需要 Python 3.10 或更新版本。内置的 debugpy 1.8.22 不支持 Python 3.9，以前在 3.9 上启动调试会直接退出、没有任何提示；现在 Lithe 会在启动调试前检查解释器版本。运行、测试和依赖树仍支持 Python 3.9。

原来的「显示类型错误」选择不会迁移到新设置：

- 选过“关闭”的，请开启「隐藏类型错误」。
- 选过“仅已配置项目”的，请把类型检查模式设为“关闭”。有自己 Pyrefly 配置的项目仍按项目配置检查。
- “仅报告缺失导入”不再提供。

已知限制：在 macOS 和 Linux 上，建在项目外的虚拟环境（`python -m venv`、`uv venv`、virtualenv，以及 Poetry、Pipenv 默认建的环境）和 Homebrew 安装的 Python 暂时不能选作解释器（[#2316](https://github.com/1lck/Lithe-IDEA/issues/2316)）。在此之前，可以把环境建在项目里的 `.venv`（Poetry 用 `poetry config virtualenvs.in-project true`，Pipenv 设 `PIPENV_VENV_IN_PROJECT=1`），或者固定 uv、pyenv、python.org 安装的解释器。

## English

- **Settings › Languages & Frameworks › Python** now shows the Python interpreter in use at the top. Click it to change it on the Toolchains page. The preview cards below draw the effect of the type checking mode, diagnostic scope, auto-import completions and function parentheses, following settings you have not saved yet.
- **Settings › Build, Execution, Deployment › Build Tools › Python** shows the order in which Lithe looks for an interpreter: the project's pinned interpreter and its `.venv`, `venv` or `.conda`, then the global setting, then automatic discovery.
- Pyrefly analysis, runs, tests and debugging all use the one interpreter the Toolchains page resolves for the project.
- **Hide type errors** replaces **Display type errors**. When it is on, no file shows type errors, including projects with their own Pyrefly config. Hover, go to definition and completion keep working.
- The type checking mode has a new **Legacy** preset. **Automatic** follows a nearby mypy or Pyright config, and checks as **Basic** when there is none.
- The descriptions of the type checking mode and the auto-import module path style now explain how they depend on other settings. For example, no preset shows type errors while **Hide type errors** is on, and with **Auto-import completions** off only code actions use the path style.

### Upgrade and compatibility

Python Support v1.1.0 requires Lithe 0.8.9 or later. Starting with 0.8.10, Lithe can also recognize extensionless scripts by their shebang.

v1.1.0 removes the **Python executable override** setting. After you upgrade, a saved path no longer applies. Pin the interpreter for the project in **Settings › Build, Execution, Deployment › Toolchains** instead.

Debugging requires Python 3.10 or later. The bundled debugpy 1.8.22 does not support Python 3.9, and starting a debug session on 3.9 used to exit without any message. Lithe now checks the interpreter version before it starts debugging. Runs, tests and the dependency tree still support Python 3.9.

Your **Display type errors** choice does not carry over to the new setting:

- If you chose **Off**, turn on **Hide type errors**.
- If you chose **Configured projects only**, set the type checking mode to **Off**. Projects with their own Pyrefly config are still checked by that config.
- **Missing imports only** is no longer available.

Known limitation: on macOS and Linux, virtual environments outside the project (made by `python -m venv`, `uv venv` or virtualenv, and the environments Poetry and Pipenv create by default) and Homebrew Python cannot be chosen as the interpreter yet ([#2316](https://github.com/1lck/Lithe-IDEA/issues/2316)). Until then, create the environment in the project as `.venv` (for Poetry, `poetry config virtualenvs.in-project true`; for Pipenv, set `PIPENV_VENV_IN_PROJECT=1`), or pin an interpreter installed by uv, pyenv or python.org.
